   58: =head1 DESCRIPTION
   59: 
   60: C<Email::Abuse::Investigator> examines the raw source of a spam/phishing e-mail
   61: and answers the questions manual abuse investigators ask:
   62: 
   63: =over 4
   64: 
   65: =item 1. Where did the message really come from?
   66: 
   67: Walks the C<Received:> chain, skips private/trusted IPs, and identifies the
   68: first external hop.  Enriches with rDNS, WHOIS/RDAP org name and abuse
   69: contact.  Both IPv4 and IPv6 addresses are supported.
   70: 
   71: =item 2. Who hosts the advertised web sites?
   72: 
   73: Extracts every C<http://> and C<https://> URL from both plain-text and HTML
   74: parts, resolves each hostname to an IP, and looks up the network owner.
   75: 
   76: =item 3. Who owns the reply-to / contact domains?
   77: 
   78: Extracts domains from C<mailto:> links, bare e-mail addresses in the body,
   79: the C<From:>/C<Reply-To:>/C<Sender:>/C<Return-Path:> headers, C<DKIM-Signature: d=>
   80: (the signing domain), C<List-Unsubscribe:> (the ESP or bulk-sender domain), and the
   81: C<Message-ID:> domain.  For each unique domain it gathers:
   82: 
   83: =over 8
   84: 
   85: =item * Domain registrar and registrant (WHOIS)
   86: 
   87: =item * Web-hosting IP and network owner (A record -> RDAP)
   88: 
   89: =item * Mail-hosting IP and network owner (MX record -> RDAP)
   90: 
   91: =item * DNS nameserver operator (NS record -> RDAP)
   92: 
   93: =item * Whether the domain was recently registered (potential flag)
   94: 
   95: =back
   96: 
   97: =back
   98: 
   99: =cut

 4597: =head1 ALGORITHM: DOMAIN INTELLIGENCE PIPELINE
 4598: 
 4599: For each unique non-infrastructure domain found in the email, the module
 4600: runs the following pipeline:
 4601: 
 4602:     Domain name
 4603:         |
 4604:         +-- A/AAAA record --> web hosting IP --> RDAP --> org + abuse contact
 4605:         |
 4606:         +-- MX record --> mail server hostname --> A --> RDAP --> org + abuse
 4607:         |
 4608:         +-- NS record --> nameserver hostname  --> A --> RDAP --> org + abuse
 4609:         |
 4610:         +-- WHOIS (TLD whois server via IANA referral)
 4611:                +-- Registrar name + abuse contact
 4612:                +-- Creation date  (-> recently-registered flag if < 180 days)
 4613:                +-- Expiry date    (-> expires-soon or expired flags)
 4614: 
 4615: Domains are collected from:
 4616: 
 4617:     From:/Reply-To:/Sender:/Return-Path: headers
 4618:     DKIM-Signature: d=  (signing domain)
 4619:     List-Unsubscribe:   (ESP / bulk sender domain)
 4620:     Message-ID:         (often reveals real sending platform)
 4621:     mailto: links and bare addresses in the body
 4622: 
 4623: =head1 CACHING
 4624: 
 4625: Two levels of caching are used:
 4626: 
 4627: =over 4
 4628: 
 4629: =item Per-message cache (C<$self-E<gt>{_domain_info}>)
 4630: 
 4631: Stores domain analysis results for the lifetime of one C<parse_email()>
 4632: call.  Invalidated by each call to C<parse_email()>.
 4633: 
 4634: =item Cross-message cache (CHI Memory driver, if C<CHI> is installed)
 4635: 
 4636: Stores IP WHOIS, DNS resolution, and domain analysis results across all
 4637: messages processed by the same process.  TTL is one hour.  Prevents
 4638: redundant WHOIS queries for infrastructure that appears in multiple
 4639: messages in the same run (e.g. a sending ISP seen in 500 spam messages).
 4640: 
 4641: =back
 4642: 
 4643: =head1 SECURITY
 4644: 
 4645: =head2 WHOIS query sanitization
 4646: 
 4647: C<_raw_whois()> strips all ASCII control characters (C<\x00>-C<\x1F> and
 4648: C<\x7F>) from C<$query> before writing it to the socket.  This prevents
 4649: WHOIS protocol injection: a maliciously crafted domain name containing
 4650: embedded C<\r\n> would otherwise smuggle a second WHOIS command into the
 4651: same TCP connection.  If stripping leaves an empty string the method
 4652: croaks immediately rather than sending a blank query.
 4653: 
 4654: =head2 RDAP IP validation
 4655: 
 4656: C<_rdap_lookup()> validates C<$ip> before interpolating it into the ARIN
 4657: RDAP URL path.  RFC 4007 IPv6 zone identifiers (C<%eth0> suffixes on
 4658: link-local addresses) are stripped first; the remaining value must match
 4659: either a dotted-quad IPv4 address or a pure hex-colon IPv6 address.  A
 4660: value that fails this check returns C<{}> immediately without making any
 4661: network call.
 4662: 
 4663: =head2 CLI path validation
 4664: 
 4665: Both C<bin/abuse_check> and C<bin/submit_abuse_report> validate the
 4666: C<$ARGV[0]> file path before opening it.  They reject any path that
 4667: contains NUL bytes or bare CR/LF characters, and independently reject
 4668: paths containing directory-traversal sequences (C<../>).  This makes the
 4669: scripts safe to invoke under C<perl -T> (taint mode) and prevents
 4670: accidental or intentional access to files outside the intended directory.
 4671: 
 4672: =head1 IPV6 SUPPORT
 4673: 
 4674: IPv6 addresses are extracted from C<Received:> headers using bracketed
 4675: notation (C<[2001:db8::1]>).  They are tested against the private range
 4676: list (which covers ::1, fe80::/10, fc00::/7, fd00::/8, and the
 4677: documentation range 2001:db8::/32) and passed through C<_whois_ip()> and
 4678: C<_rdap_lookup()> in the same way as IPv4 addresses.  RFC 4007 zone
 4679: identifiers (e.g. C<%eth0>) are stripped by C<_rdap_lookup()> before the
 4680: address is placed in the RDAP URL.
 4681: 
 4682: C<_resolve_host()> attempts both A and AAAA lookups when C<Net::DNS> is
 4683: installed.  C<_raw_whois()> uses C<IO::Socket::IP> for dual-stack WHOIS
 4684: connections when that module is installed.

 4767: =head1 LIMITATIONS
 4768: 
 4769: =over 4
 4770: 
 4771: =item No charset conversion
 4772: 
 4773: Body text is stored as raw bytes.  Non-ASCII content (UTF-8, Latin-1,
 4774: ISO-2022-JP, etc.) is not decoded to Perl's internal Unicode representation.
 4775: URL and domain extraction from non-ASCII bodies may miss or misparse content.
 4776: Use C<Email::MIME> if full charset support is needed.
 4777: 
 4778: =item Hand-rolled MIME parser
 4779: 
 4780: The built-in MIME parser handles common cases but is not a conforming
 4781: implementation of RFC 2045/2046.  It silently drops parts it cannot decode,
 4782: does not handle C<message/rfc822> attachments, and does not parse
 4783: C<Content-Disposition> filenames.  Replace with C<Email::MIME> or
 4784: C<MIME::Entity> for production use with untrusted input.
 4785: 
 4786: =item IPv4-only CIDR matching for trusted_relays
 4787: 
 4788: C<_ip_in_cidr()> and the C<trusted_relays> constructor argument only support
 4789: IPv4 CIDR notation.  IPv6 trusted relay entries are accepted but silently
 4790: never match.
 4791: 
 4792: =item WHOIS rate-limiting not handled
 4793: 
 4794: C<_raw_whois()> does not retry on rate-limit responses (typically a
 4795: "quota exceeded" reply).  Under high-volume processing the module will
 4796: silently return empty enrichment data for affected IPs and domains.
 4797: 
 4798: =item Not thread-safe
 4799: 
 4800: The class-level C<$_cache> variable and the optional-module C<$HAS_*> flags
 4801: are shared across all threads.  Create a separate object per thread and do
 4802: not share objects across threads.
 4803: 
 4804: =item DMARC policy not fetched
 4805: 
 4806: The module reads the C<Authentication-Results: dmarc=> result from the
 4807: message headers but does not perform live C<_dmarc.domain> TXT record
 4808: lookups.  A missing DMARC result in the headers is not independently flagged.
 4809: 
 4810: =item C<abuse_contacts()> routes duplicated in C<form_contacts()>
 4811: 
 4812: Both methods iterate the same six discovery routes independently.  Any new
 4813: discovery route must be added to both.  A future refactor should share a
 4814: single routing pass.
 4815: 
 4816: =item CHI cache is a class-level mutable global
 4817: 
 4818: The cross-message cache is shared across all instances in the process.
 4819: Tests that populate the cache will affect subsequent tests.  Pass the cache
 4820: in via C<new()> (not currently supported) to enable proper isolation.
 4821: 
 4822: =back
