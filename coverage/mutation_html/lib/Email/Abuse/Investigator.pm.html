   58: =head1 DESCRIPTION
   59: 
   60: C<Email::Abuse::Investigator> examines the raw source of a spam/phishing e-mail
   61: and answers the questions manual abuse investigators ask:
   62: 
   63: =over 4
   64: 
   65: =item 1. Where did the message really come from?
   66: 
   67: Walks the C<Received:> chain, skips private/trusted IPs, and identifies the
   68: first external hop.  Enriches with rDNS, WHOIS/RDAP org name and abuse
   69: contact.  Both IPv4 and IPv6 addresses are supported.
   70: 
   71: =item 2. Who hosts the advertised web sites?
   72: 
   73: Extracts every C<http://> and C<https://> URL from both plain-text and HTML
   74: parts, resolves each hostname to an IP, and looks up the network owner.
   75: 
   76: =item 3. Who owns the reply-to / contact domains?
   77: 
   78: Extracts domains from C<mailto:> links, bare e-mail addresses in the body,
   79: the C<From:>/C<Reply-To:>/C<Sender:>/C<Return-Path:> headers, C<DKIM-Signature: d=>
   80: (the signing domain), C<List-Unsubscribe:> (the ESP or bulk-sender domain), and the
   81: C<Message-ID:> domain.  For each unique domain it gathers:
   82: 
   83: =over 8
   84: 
   85: =item * Domain registrar and registrant (WHOIS)
   86: 
   87: =item * Web-hosting IP and network owner (A record -> RDAP)
   88: 
   89: =item * Mail-hosting IP and network owner (MX record -> RDAP)
   90: 
   91: =item * DNS nameserver operator (NS record -> RDAP)
   92: 
   93: =item * Whether the domain was recently registered (potential flag)
   94: 
   95: =back
   96: 
   97: =back
   98: 
   99: =cut

 4602: =head1 ALGORITHM: DOMAIN INTELLIGENCE PIPELINE
 4603: 
 4604: For each unique non-infrastructure domain found in the email, the module
 4605: runs the following pipeline:
 4606: 
 4607:     Domain name
 4608:         |
 4609:         +-- A/AAAA record --> web hosting IP --> RDAP --> org + abuse contact
 4610:         |
 4611:         +-- MX record --> mail server hostname --> A --> RDAP --> org + abuse
 4612:         |
 4613:         +-- NS record --> nameserver hostname  --> A --> RDAP --> org + abuse
 4614:         |
 4615:         +-- WHOIS (TLD whois server via IANA referral)
 4616:                +-- Registrar name + abuse contact
 4617:                +-- Creation date  (-> recently-registered flag if < 180 days)
 4618:                +-- Expiry date    (-> expires-soon or expired flags)
 4619: 
 4620: Domains are collected from:
 4621: 
 4622:     From:/Reply-To:/Sender:/Return-Path: headers
 4623:     DKIM-Signature: d=  (signing domain)
 4624:     List-Unsubscribe:   (ESP / bulk sender domain)
 4625:     Message-ID:         (often reveals real sending platform)
 4626:     mailto: links and bare addresses in the body
 4627: 
 4628: =head1 CACHING
 4629: 
 4630: Two levels of caching are used:
 4631: 
 4632: =over 4
 4633: 
 4634: =item Per-message cache (C<$self-E<gt>{_domain_info}>)
 4635: 
 4636: Stores domain analysis results for the lifetime of one C<parse_email()>
 4637: call.  Invalidated by each call to C<parse_email()>.
 4638: 
 4639: =item Cross-message cache (CHI Memory driver, if C<CHI> is installed)
 4640: 
 4641: Stores IP WHOIS, DNS resolution, and domain analysis results across all
 4642: messages processed by the same process.  TTL is one hour.  Prevents
 4643: redundant WHOIS queries for infrastructure that appears in multiple
 4644: messages in the same run (e.g. a sending ISP seen in 500 spam messages).
 4645: 
 4646: =back
 4647: 
 4648: =head1 SECURITY
 4649: 
 4650: =head2 WHOIS query sanitization
 4651: 
 4652: C<_raw_whois()> strips all ASCII control characters (C<\x00>-C<\x1F> and
 4653: C<\x7F>) from C<$query> before writing it to the socket.  This prevents
 4654: WHOIS protocol injection: a maliciously crafted domain name containing
 4655: embedded C<\r\n> would otherwise smuggle a second WHOIS command into the
 4656: same TCP connection.  If stripping leaves an empty string the method
 4657: croaks immediately rather than sending a blank query.
 4658: 
 4659: =head2 RDAP IP validation
 4660: 
 4661: C<_rdap_lookup()> validates C<$ip> before interpolating it into the ARIN
 4662: RDAP URL path.  RFC 4007 IPv6 zone identifiers (C<%eth0> suffixes on
 4663: link-local addresses) are stripped first; the remaining value must match
 4664: either a dotted-quad IPv4 address or a pure hex-colon IPv6 address.  A
 4665: value that fails this check returns C<{}> immediately without making any
 4666: network call.
 4667: 
 4668: =head2 CLI path validation
 4669: 
 4670: Both C<bin/abuse_check> and C<bin/submit_abuse_report> validate the
 4671: C<$ARGV[0]> file path before opening it.  They reject any path that
 4672: contains NUL bytes or bare CR/LF characters, and independently reject
 4673: paths containing directory-traversal sequences (C<../>).  This makes the
 4674: scripts safe to invoke under C<perl -T> (taint mode) and prevents
 4675: accidental or intentional access to files outside the intended directory.
 4676: 
 4677: =head1 IPV6 SUPPORT
 4678: 
 4679: IPv6 addresses are extracted from C<Received:> headers using bracketed
 4680: notation (C<[2001:db8::1]>).  They are tested against the private range
 4681: list (which covers ::1, fe80::/10, fc00::/7, fd00::/8, and the
 4682: documentation range 2001:db8::/32) and passed through C<_whois_ip()> and
 4683: C<_rdap_lookup()> in the same way as IPv4 addresses.  RFC 4007 zone
 4684: identifiers (e.g. C<%eth0>) are stripped by C<_rdap_lookup()> before the
 4685: address is placed in the RDAP URL.
 4686: 
 4687: C<_resolve_host()> attempts both A and AAAA lookups when C<Net::DNS> is
 4688: installed.  C<_raw_whois()> uses C<IO::Socket::IP> for dual-stack WHOIS
 4689: connections when that module is installed.

 4772: =head1 LIMITATIONS
 4773: 
 4774: =over 4
 4775: 
 4776: =item No charset conversion
 4777: 
 4778: Body text is stored as raw bytes.  Non-ASCII content (UTF-8, Latin-1,
 4779: ISO-2022-JP, etc.) is not decoded to Perl's internal Unicode representation.
 4780: URL and domain extraction from non-ASCII bodies may miss or misparse content.
 4781: Use C<Email::MIME> if full charset support is needed.
 4782: 
 4783: =item Hand-rolled MIME parser
 4784: 
 4785: The built-in MIME parser handles common cases but is not a conforming
 4786: implementation of RFC 2045/2046.  It silently drops parts it cannot decode,
 4787: does not handle C<message/rfc822> attachments, and does not parse
 4788: C<Content-Disposition> filenames.  Replace with C<Email::MIME> or
 4789: C<MIME::Entity> for production use with untrusted input.
 4790: 
 4791: =item IPv4-only CIDR matching for trusted_relays
 4792: 
 4793: C<_ip_in_cidr()> and the C<trusted_relays> constructor argument only support
 4794: IPv4 CIDR notation.  IPv6 trusted relay entries are accepted but silently
 4795: never match.
 4796: 
 4797: =item WHOIS rate-limiting not handled
 4798: 
 4799: C<_raw_whois()> does not retry on rate-limit responses (typically a
 4800: "quota exceeded" reply).  Under high-volume processing the module will
 4801: silently return empty enrichment data for affected IPs and domains.
 4802: 
 4803: =item Not thread-safe
 4804: 
 4805: The class-level C<$_cache> variable and the optional-module C<$HAS_*> flags
 4806: are shared across all threads.  Create a separate object per thread and do
 4807: not share objects across threads.
 4808: 
 4809: =item DMARC policy not fetched
 4810: 
 4811: The module reads the C<Authentication-Results: dmarc=> result from the
 4812: message headers but does not perform live C<_dmarc.domain> TXT record
 4813: lookups.  A missing DMARC result in the headers is not independently flagged.
 4814: 
 4815: =item C<abuse_contacts()> routes duplicated in C<form_contacts()>
 4816: 
 4817: Both methods iterate the same six discovery routes independently.  Any new
 4818: discovery route must be added to both.  A future refactor should share a
 4819: single routing pass.
 4820: 
 4821: =item CHI cache is a class-level mutable global
 4822: 
 4823: The cross-message cache is shared across all instances in the process.
 4824: Tests that populate the cache will affect subsequent tests.  Pass the cache
 4825: in via C<new()> (not currently supported) to enable proper isolation.
 4826: 
 4827: =back
