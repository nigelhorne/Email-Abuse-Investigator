   43: =head1 DESCRIPTION
   44: 
   45: C<Email::Abuse::Investigator> examines the raw source of a spam/phishing e-mail
   46: and answers the questions manual abuse investigators ask:
   47: 
   48: =over 4
   49: 
   50: =item 1. Where did the message really come from?
   51: 
   52: Walks the C<Received:> chain, skips private/trusted IPs, and identifies the
   53: first external hop.  Enriches with rDNS, WHOIS/RDAP org name and abuse
   54: contact.  Both IPv4 and IPv6 addresses are supported.
   55: 
   56: =item 2. Who hosts the advertised web sites?
   57: 
   58: Extracts every C<http://> and C<https://> URL from both plain-text and HTML
   59: parts, resolves each hostname to an IP, and looks up the network owner.
   60: 
   61: =item 3. Who owns the reply-to / contact domains?
   62: 
   63: Extracts domains from C<mailto:> links, bare e-mail addresses in the body,
   64: the C<From:>/C<Reply-To:>/C<Sender:>/C<Return-Path:> headers, C<DKIM-Signature: d=>
   65: (the signing domain), C<List-Unsubscribe:> (the ESP or bulk-sender domain), and the
   66: C<Message-ID:> domain.  For each unique domain it gathers:
   67: 
   68: =over 8
   69: 
   70: =item * Domain registrar and registrant (WHOIS)
   71: 
   72: =item * Web-hosting IP and network owner (A record -> RDAP)
   73: 
   74: =item * Mail-hosting IP and network owner (MX record -> RDAP)
   75: 
   76: =item * DNS nameserver operator (NS record -> RDAP)
   77: 
   78: =item * Whether the domain was recently registered (potential flag)
   79: 
   80: =back
   81: 
   82: =back

 4246: =head1 ALGORITHM: DOMAIN INTELLIGENCE PIPELINE
 4247: 
 4248: For each unique non-infrastructure domain found in the email, the module
 4249: runs the following pipeline:
 4250: 
 4251:     Domain name
 4252:         |
 4253:         +-- A/AAAA record --> web hosting IP --> RDAP --> org + abuse contact
 4254:         |
 4255:         +-- MX record --> mail server hostname --> A --> RDAP --> org + abuse
 4256:         |
 4257:         +-- NS record --> nameserver hostname  --> A --> RDAP --> org + abuse
 4258:         |
 4259:         +-- WHOIS (TLD whois server via IANA referral)
 4260:                +-- Registrar name + abuse contact
 4261:                +-- Creation date  (-> recently-registered flag if < 180 days)
 4262:                +-- Expiry date    (-> expires-soon or expired flags)
 4263: 
 4264: Domains are collected from:
 4265: 
 4266:     From:/Reply-To:/Sender:/Return-Path: headers
 4267:     DKIM-Signature: d=  (signing domain)
 4268:     List-Unsubscribe:   (ESP / bulk sender domain)
 4269:     Message-ID:         (often reveals real sending platform)
 4270:     mailto: links and bare addresses in the body
 4271: 
 4272: =head1 CACHING
 4273: 
 4274: Two levels of caching are used:
 4275: 
 4276: =over 4
 4277: 
 4278: =item Per-message cache (C<$self-E<gt>{_domain_info}>)
 4279: 
 4280: Stores domain analysis results for the lifetime of one C<parse_email()>
 4281: call.  Invalidated by each call to C<parse_email()>.
 4282: 
 4283: =item Cross-message cache (CHI Memory driver, if C<CHI> is installed)
 4284: 
 4285: Stores IP WHOIS, DNS resolution, and domain analysis results across all
 4286: messages processed by the same process.  TTL is one hour.  Prevents
 4287: redundant WHOIS queries for infrastructure that appears in multiple
 4288: messages in the same run (e.g. a sending ISP seen in 500 spam messages).
 4289: 
 4290: =back
 4291: 
 4292: =head1 IPV6 SUPPORT
 4293: 
 4294: IPv6 addresses are extracted from C<Received:> headers using bracketed
 4295: notation (C<[2001:db8::1]>).  They are tested against the private range
 4296: list (which covers ::1, fe80::/10, fc00::/7, fd00::/8, and the
 4297: documentation range 2001:db8::/32) and passed through C<_whois_ip()> and
 4298: C<_rdap_lookup()> in the same way as IPv4 addresses.
 4299: 
 4300: C<_resolve_host()> attempts both A and AAAA lookups when C<Net::DNS> is
 4301: installed.  C<_raw_whois()> uses C<IO::Socket::IP> for dual-stack WHOIS
 4302: connections when that module is installed.
