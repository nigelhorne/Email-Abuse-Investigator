   55: =head1 DESCRIPTION
   56: 
   57: C<Email::Abuse::Investigator> examines the raw source of a spam/phishing e-mail
   58: and answers the questions manual abuse investigators ask:
   59: 
   60: =over 4
   61: 
   62: =item 1. Where did the message really come from?
   63: 
   64: Walks the C<Received:> chain, skips private/trusted IPs, and identifies the
   65: first external hop.  Enriches with rDNS, WHOIS/RDAP org name and abuse
   66: contact.  Both IPv4 and IPv6 addresses are supported.
   67: 
   68: =item 2. Who hosts the advertised web sites?
   69: 
   70: Extracts every C<http://> and C<https://> URL from both plain-text and HTML
   71: parts, resolves each hostname to an IP, and looks up the network owner.
   72: 
   73: =item 3. Who owns the reply-to / contact domains?
   74: 
   75: Extracts domains from C<mailto:> links, bare e-mail addresses in the body,
   76: the C<From:>/C<Reply-To:>/C<Sender:>/C<Return-Path:> headers, C<DKIM-Signature: d=>
   77: (the signing domain), C<List-Unsubscribe:> (the ESP or bulk-sender domain), and the
   78: C<Message-ID:> domain.  For each unique domain it gathers:
   79: 
   80: =over 8
   81: 
   82: =item * Domain registrar and registrant (WHOIS)
   83: 
   84: =item * Web-hosting IP and network owner (A record -> RDAP)
   85: 
   86: =item * Mail-hosting IP and network owner (MX record -> RDAP)
   87: 
   88: =item * DNS nameserver operator (NS record -> RDAP)
   89: 
   90: =item * Whether the domain was recently registered (potential flag)
   91: 
   92: =back
   93: 
   94: =back

 4312: =head1 ALGORITHM: DOMAIN INTELLIGENCE PIPELINE
 4313: 
 4314: For each unique non-infrastructure domain found in the email, the module
 4315: runs the following pipeline:
 4316: 
 4317:     Domain name
 4318:         |
 4319:         +-- A/AAAA record --> web hosting IP --> RDAP --> org + abuse contact
 4320:         |
 4321:         +-- MX record --> mail server hostname --> A --> RDAP --> org + abuse
 4322:         |
 4323:         +-- NS record --> nameserver hostname  --> A --> RDAP --> org + abuse
 4324:         |
 4325:         +-- WHOIS (TLD whois server via IANA referral)
 4326:                +-- Registrar name + abuse contact
 4327:                +-- Creation date  (-> recently-registered flag if < 180 days)
 4328:                +-- Expiry date    (-> expires-soon or expired flags)
 4329: 
 4330: Domains are collected from:
 4331: 
 4332:     From:/Reply-To:/Sender:/Return-Path: headers
 4333:     DKIM-Signature: d=  (signing domain)
 4334:     List-Unsubscribe:   (ESP / bulk sender domain)
 4335:     Message-ID:         (often reveals real sending platform)
 4336:     mailto: links and bare addresses in the body
 4337: 
 4338: =head1 CACHING
 4339: 
 4340: Two levels of caching are used:
 4341: 
 4342: =over 4
 4343: 
 4344: =item Per-message cache (C<$self-E<gt>{_domain_info}>)
 4345: 
 4346: Stores domain analysis results for the lifetime of one C<parse_email()>
 4347: call.  Invalidated by each call to C<parse_email()>.
 4348: 
 4349: =item Cross-message cache (CHI Memory driver, if C<CHI> is installed)
 4350: 
 4351: Stores IP WHOIS, DNS resolution, and domain analysis results across all
 4352: messages processed by the same process.  TTL is one hour.  Prevents
 4353: redundant WHOIS queries for infrastructure that appears in multiple
 4354: messages in the same run (e.g. a sending ISP seen in 500 spam messages).
 4355: 
 4356: =back

 4358: =head1 IPV6 SUPPORT
 4359: 
 4360: IPv6 addresses are extracted from C<Received:> headers using bracketed
 4361: notation (C<[2001:db8::1]>).  They are tested against the private range
 4362: list (which covers ::1, fe80::/10, fc00::/7, fd00::/8, and the
 4363: documentation range 2001:db8::/32) and passed through C<_whois_ip()> and
 4364: C<_rdap_lookup()> in the same way as IPv4 addresses.
 4365: 
 4366: C<_resolve_host()> attempts both A and AAAA lookups when C<Net::DNS> is
 4367: installed.  C<_raw_whois()> uses C<IO::Socket::IP> for dual-stack WHOIS
 4368: connections when that module is installed.
