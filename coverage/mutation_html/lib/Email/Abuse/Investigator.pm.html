   58: =head1 DESCRIPTION
   59: 
   60: C<Email::Abuse::Investigator> examines the raw source of a spam/phishing e-mail
   61: and answers the questions manual abuse investigators ask:
   62: 
   63: =over 4
   64: 
   65: =item 1. Where did the message really come from?
   66: 
   67: Walks the C<Received:> chain, skips private/trusted IPs, and identifies the
   68: first external hop.  Enriches with rDNS, WHOIS/RDAP org name and abuse
   69: contact.  Both IPv4 and IPv6 addresses are supported.
   70: 
   71: =item 2. Who hosts the advertised web sites?
   72: 
   73: Extracts every C<http://> and C<https://> URL from both plain-text and HTML
   74: parts, resolves each hostname to an IP, and looks up the network owner.
   75: 
   76: =item 3. Who owns the reply-to / contact domains?
   77: 
   78: Extracts domains from C<mailto:> links, bare e-mail addresses in the body,
   79: the C<From:>/C<Reply-To:>/C<Sender:>/C<Return-Path:> headers, C<DKIM-Signature: d=>
   80: (the signing domain), C<List-Unsubscribe:> (the ESP or bulk-sender domain), and the
   81: C<Message-ID:> domain.  For each unique domain it gathers:
   82: 
   83: =over 8
   84: 
   85: =item * Domain registrar and registrant (WHOIS)
   86: 
   87: =item * Web-hosting IP and network owner (A record -> RDAP)
   88: 
   89: =item * Mail-hosting IP and network owner (MX record -> RDAP)
   90: 
   91: =item * DNS nameserver operator (NS record -> RDAP)
   92: 
   93: =item * Whether the domain was recently registered (potential flag)
   94: 
   95: =back
   96: 
   97: =back
   98: 
   99: =cut

 4266: =head1 ALGORITHM: DOMAIN INTELLIGENCE PIPELINE
 4267: 
 4268: For each unique non-infrastructure domain found in the email, the module
 4269: runs the following pipeline:
 4270: 
 4271:     Domain name
 4272:         |
 4273:         +-- A/AAAA record --> web hosting IP --> RDAP --> org + abuse contact
 4274:         |
 4275:         +-- MX record --> mail server hostname --> A --> RDAP --> org + abuse
 4276:         |
 4277:         +-- NS record --> nameserver hostname  --> A --> RDAP --> org + abuse
 4278:         |
 4279:         +-- WHOIS (TLD whois server via IANA referral)
 4280:                +-- Registrar name + abuse contact
 4281:                +-- Creation date  (-> recently-registered flag if < 180 days)
 4282:                +-- Expiry date    (-> expires-soon or expired flags)
 4283: 
 4284: Domains are collected from:
 4285: 
 4286:     From:/Reply-To:/Sender:/Return-Path: headers
 4287:     DKIM-Signature: d=  (signing domain)
 4288:     List-Unsubscribe:   (ESP / bulk sender domain)
 4289:     Message-ID:         (often reveals real sending platform)
 4290:     mailto: links and bare addresses in the body
 4291: 
 4292: =head1 CACHING
 4293: 
 4294: Two levels of caching are used:
 4295: 
 4296: =over 4
 4297: 
 4298: =item Per-message cache (C<$self-E<gt>{_domain_info}>)
 4299: 
 4300: Stores domain analysis results for the lifetime of one C<parse_email()>
 4301: call.  Invalidated by each call to C<parse_email()>.
 4302: 
 4303: =item Cross-message cache (CHI Memory driver, if C<CHI> is installed)
 4304: 
 4305: Stores IP WHOIS, DNS resolution, and domain analysis results across all
 4306: messages processed by the same process.  TTL is one hour.  Prevents
 4307: redundant WHOIS queries for infrastructure that appears in multiple
 4308: messages in the same run (e.g. a sending ISP seen in 500 spam messages).
 4309: 
 4310: =back
 4311: 
 4312: =head1 IPV6 SUPPORT
 4313: 
 4314: IPv6 addresses are extracted from C<Received:> headers using bracketed
 4315: notation (C<[2001:db8::1]>).  They are tested against the private range
 4316: list (which covers ::1, fe80::/10, fc00::/7, fd00::/8, and the
 4317: documentation range 2001:db8::/32) and passed through C<_whois_ip()> and
 4318: C<_rdap_lookup()> in the same way as IPv4 addresses.
 4319: 
 4320: C<_resolve_host()> attempts both A and AAAA lookups when C<Net::DNS> is
 4321: installed.  C<_raw_whois()> uses C<IO::Socket::IP> for dual-stack WHOIS
 4322: connections when that module is installed.

 4400: =head1 LIMITATIONS
 4401: 
 4402: =over 4
 4403: 
 4404: =item No charset conversion
 4405: 
 4406: Body text is stored as raw bytes.  Non-ASCII content (UTF-8, Latin-1,
 4407: ISO-2022-JP, etc.) is not decoded to Perl's internal Unicode representation.
 4408: URL and domain extraction from non-ASCII bodies may miss or misparse content.
 4409: Use C<Email::MIME> if full charset support is needed.
 4410: 
 4411: =item Hand-rolled MIME parser
 4412: 
 4413: The built-in MIME parser handles common cases but is not a conforming
 4414: implementation of RFC 2045/2046.  It silently drops parts it cannot decode,
 4415: does not handle C<message/rfc822> attachments, and does not parse
 4416: C<Content-Disposition> filenames.  Replace with C<Email::MIME> or
 4417: C<MIME::Entity> for production use with untrusted input.
 4418: 
 4419: =item IPv4-only CIDR matching for trusted_relays
 4420: 
 4421: C<_ip_in_cidr()> and the C<trusted_relays> constructor argument only support
 4422: IPv4 CIDR notation.  IPv6 trusted relay entries are accepted but silently
 4423: never match.
 4424: 
 4425: =item WHOIS rate-limiting not handled
 4426: 
 4427: C<_raw_whois()> does not retry on rate-limit responses (typically a
 4428: "quota exceeded" reply).  Under high-volume processing the module will
 4429: silently return empty enrichment data for affected IPs and domains.
 4430: 
 4431: =item Not thread-safe
 4432: 
 4433: The class-level C<$_cache> variable and the optional-module C<$HAS_*> flags
 4434: are shared across all threads.  Create a separate object per thread and do
 4435: not share objects across threads.
 4436: 
 4437: =item DMARC policy not fetched
 4438: 
 4439: The module reads the C<Authentication-Results: dmarc=> result from the
 4440: message headers but does not perform live C<_dmarc.domain> TXT record
 4441: lookups.  A missing DMARC result in the headers is not independently flagged.
 4442: 
 4443: =item C<abuse_contacts()> routes duplicated in C<form_contacts()>
 4444: 
 4445: Both methods iterate the same six discovery routes independently.  Any new
 4446: discovery route must be added to both.  A future refactor should share a
 4447: single routing pass.
 4448: 
 4449: =item CHI cache is a class-level mutable global
 4450: 
 4451: The cross-message cache is shared across all instances in the process.
 4452: Tests that populate the cache will affect subsequent tests.  Pass the cache
 4453: in via C<new()> (not currently supported) to enable proper isolation.
 4454:
