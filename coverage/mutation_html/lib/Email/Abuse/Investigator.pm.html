   42: =head1 DESCRIPTION
   43: 
   44: C<Email::Abuse::Investigator> examines the raw source of a spam/phishing e-mail
   45: and answers the questions manual abuse investigators ask:
   46: 
   47: =over 4
   48: 
   49: =item 1. Where did the message really come from?
   50: 
   51: Walks the C<Received:> chain, skips private/trusted IPs, and identifies the
   52: first external hop.  Enriches with rDNS, WHOIS/RDAP org name and abuse
   53: contact.  Both IPv4 and IPv6 addresses are supported.
   54: 
   55: =item 2. Who hosts the advertised web sites?
   56: 
   57: Extracts every C<http://> and C<https://> URL from both plain-text and HTML
   58: parts, resolves each hostname to an IP, and looks up the network owner.
   59: 
   60: =item 3. Who owns the reply-to / contact domains?
   61: 
   62: Extracts domains from C<mailto:> links, bare e-mail addresses in the body,
   63: the C<From:>/C<Reply-To:>/C<Sender:>/C<Return-Path:> headers, C<DKIM-Signature: d=>
   64: (the signing domain), C<List-Unsubscribe:> (the ESP or bulk-sender domain), and the
   65: C<Message-ID:> domain.  For each unique domain it gathers:
   66: 
   67: =over 8
   68: 
   69: =item * Domain registrar and registrant (WHOIS)
   70: 
   71: =item * Web-hosting IP and network owner (A record -> RDAP)
   72: 
   73: =item * Mail-hosting IP and network owner (MX record -> RDAP)
   74: 
   75: =item * DNS nameserver operator (NS record -> RDAP)
   76: 
   77: =item * Whether the domain was recently registered (potential flag)
   78: 
   79: =back
   80: 
   81: =back

 4245: =head1 ALGORITHM: DOMAIN INTELLIGENCE PIPELINE
 4246: 
 4247: For each unique non-infrastructure domain found in the email, the module
 4248: runs the following pipeline:
 4249: 
 4250:     Domain name
 4251:         |
 4252:         +-- A/AAAA record --> web hosting IP --> RDAP --> org + abuse contact
 4253:         |
 4254:         +-- MX record --> mail server hostname --> A --> RDAP --> org + abuse
 4255:         |
 4256:         +-- NS record --> nameserver hostname  --> A --> RDAP --> org + abuse
 4257:         |
 4258:         +-- WHOIS (TLD whois server via IANA referral)
 4259:                +-- Registrar name + abuse contact
 4260:                +-- Creation date  (-> recently-registered flag if < 180 days)
 4261:                +-- Expiry date    (-> expires-soon or expired flags)
 4262: 
 4263: Domains are collected from:
 4264: 
 4265:     From:/Reply-To:/Sender:/Return-Path: headers
 4266:     DKIM-Signature: d=  (signing domain)
 4267:     List-Unsubscribe:   (ESP / bulk sender domain)
 4268:     Message-ID:         (often reveals real sending platform)
 4269:     mailto: links and bare addresses in the body
 4270: 
 4271: =head1 CACHING
 4272: 
 4273: Two levels of caching are used:
 4274: 
 4275: =over 4
 4276: 
 4277: =item Per-message cache (C<$self-E<gt>{_domain_info}>)
 4278: 
 4279: Stores domain analysis results for the lifetime of one C<parse_email()>
 4280: call.  Invalidated by each call to C<parse_email()>.
 4281: 
 4282: =item Cross-message cache (CHI Memory driver, if C<CHI> is installed)
 4283: 
 4284: Stores IP WHOIS, DNS resolution, and domain analysis results across all
 4285: messages processed by the same process.  TTL is one hour.  Prevents
 4286: redundant WHOIS queries for infrastructure that appears in multiple
 4287: messages in the same run (e.g. a sending ISP seen in 500 spam messages).
 4288: 
 4289: =back
 4290: 
 4291: =head1 IPV6 SUPPORT
 4292: 
 4293: IPv6 addresses are extracted from C<Received:> headers using bracketed
 4294: notation (C<[2001:db8::1]>).  They are tested against the private range
 4295: list (which covers ::1, fe80::/10, fc00::/7, fd00::/8, and the
 4296: documentation range 2001:db8::/32) and passed through C<_whois_ip()> and
 4297: C<_rdap_lookup()> in the same way as IPv4 addresses.
 4298: 
 4299: C<_resolve_host()> attempts both A and AAAA lookups when C<Net::DNS> is
 4300: installed.  C<_raw_whois()> uses C<IO::Socket::IP> for dual-stack WHOIS
 4301: connections when that module is installed.
